# Performance

The interface is same-origin static assets with no frontend framework, fonts, images, or third-party scripts. Lists are bounded and paginated (25 by default, max 100); indexes support member and attendance sort order and primary keys support other reverse-ID listings. SQLite writes and audit events are atomic. Responses with personal data are not cached.

No performance benchmarks, query plans, load tests, accessibility audits, or poor-network simulations have been run. Offset pagination gets more expensive at high offsets and can shift as records are inserted. SQLite serializes writes; a single-process login limiter and SQLite deployment are not a horizontal-scaling design. There is no offline queue, service worker, retries, image pipeline or code splitting (assets are small and unbundled). Test on representative Android devices and poor networks, measure latency and query plans with synthetic data, and add cursor pagination and a managed DB as needed. Protect API payload and connection sizes at the edge.
