# Testing

Run the README checks with synthetic data. Automated tests use a fresh temporary SQLite database and FastAPI TestClient, covering every role's permissions, authentication, logout, CSRF, session expiry and account deactivation, validation, pagination, audit creation, shared and concurrent rate limiting, bounded bodies, credential redaction, account-management races, headers, persistence and backup and restore overwrite protection/integrity and session revocation, legacy schema upgrades, optimistic member edits/deletes, and atomic CSV imports. `node --check` checks JavaScript syntax only; it is not a browser interaction or accessibility test. `compileall` checks Python compilation; `python -m build --no-isolation` builds a wheel and source distribution, and `tools/check_wheel.py` checks required asset presence. `pip-audit` checks the resolved runtime and development dependencies against its advisory source; a clean result is not proof of security.

Before release add browser end-to-end tests on mobile/desktop, keyboard and screen-reader tests, concurrency and load tests, proxy/TLS tests, restore drills, accessibility tooling and independent penetration testing. CI results are only known after the hosted workflow runs.
